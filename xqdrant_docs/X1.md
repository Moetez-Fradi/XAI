# Cross-cut X1 — SIMD gather vs repack kernels

**Status:** implemented on the same branch as Option 2 (`option2-hybrid-layer-cutoff`).
Does **not** change `mask_from_layer` semantics — only the per-comparison kernel inside
`MaskedMetricQueryScorer`.

**Goal:** Make `focus.masked` / hybrid `mask_from_layer` actually faster than full search
when `D_sub < D`. Option 2 measurements showed recall recovery but speedup &lt; 1 because
the masked scorer was always **repacking** into a scratch buffer then calling contiguous
SIMD — that copy dominates at small/medium `D_sub`.

## What was added

### Two kernels

| Kernel | Behaviour |
|--------|-----------|
| **repack** (default) | Copy focus dims of the stored vector into a contiguous scratch buffer, then call the normal contiguous SIMD metric (`TMetric::similarity`). |
| **gather** | Score focus dims in place. On x86_64 with AVX2+FMA: `_mm256_i32gather_ps` (`vgatherdps`) for Dot/Cosine/Euclid. Elsewhere / Manhattan: scalar gather loop. Non-`f32` element types fall back to repack. |

### Runtime selection

```bash
# default
XQDRANT_MASKED_KERNEL=repack   # or unset

# experimental gather path
XQDRANT_MASKED_KERNEL=gather
```

Resolved once via `MaskedKernelMode::from_env()` when the scorer is built.

### Criterion bench → CSV

`lib/segment/benches/masked_kernel_bench.rs` measures Dot over non-contiguous focus dims
at `D_sub ∈ {32, 128, 192, 384, 768}` (full dim = 1536) and writes:

```
d_sub,kernel,ns_per_op
32,repack,...
32,gather,...
...
```

Plot side: `DB_systems/research/xcut1_gather_vs_repack/plot_xcut1_kernel_bench.py --kernel-csv …`

## Measured results (authoritative, 2026-10-05, host B: Ryzen 5 220, AVX2)

Canonical: `DB_systems/research/xcut1_gather_vs_repack/results_2026-10-05_hostB/`
(microbench, engine fork commit `6cb79ea`) and
`DB_systems/research/inengine_checks/results_2026-10-05_hostB/` (in-engine, interleaved).

**Microbench (ns per distance, SIFT width, Euclid D=128, T=5):** contiguous full 128-d
distance 18.3 ns; masked distance over 32 / 96 / 128 dims: repack 36.4 / 65.1 / 81.9 ns,
gather 36.9 / 78.4 / 94.5 ns. Gather ties repack at 32 dims and is 15–20% slower above;
at D=1536 it is about 2× slower for 128+ dims. Either kernel costs 2–5× a full contiguous
distance, which is what rules out a latency win.

**In-engine (SIFT1M, M1 speed vs plain at ratios 0.25 / 0.75 / 1.0):** repack 0.82× / 0.65× /
0.63×, gather 0.84× / 0.67× / 0.65× — within 3%.

**Superseded:** the 2026-07-11 microbench (`2026-07-11_16-02-59__xcut1_…`, Apple M2) reported
gather 1.1–1.8× faster than repack. It passed the *scalar* `simple::dot_similarity` to repack
(the engine uses SIMD `Metric::similarity`), and on aarch64 gather is the scalar loop, so it
did not measure either engine path.

## Keep / skip

| Role | Decision |
|------|----------|
| Gather kernel | **Skip** — no faster than repack in isolation; within 3% in-engine. Repack stays the default. |
| “Masked search is faster e2e” | **Not supported** with either kernel. |

Live server: `XQDRANT_MASKED_KERNEL=gather ./target/release/xqdrant`.
