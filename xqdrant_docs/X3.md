# Cross-cut X3 — Fallback / verify pass (`focus.verify`)

**Status:** implemented on the Option 2 / X1 branch. Does **not** change
`mask_from_layer` or the gather/repack kernels — only adds an optional final
full-distance rescore of the returned top-k after masked / hybrid traversal.

**Goal:** Turn masked search into a *fast filter* with a correctness safety net.
Motivating finding: hybrid recovers navigability on SIFT, but high-D synthetic
recall still plateaus (~0.15–0.22). If candidates are in the ballpark, a cheap
full-distance rescore of top-k can recover recall.

## Semantics

| `focus` fields | Behaviour |
|----------------|-----------|
| `masked=true`, `verify` omitted/false | Identical to Option 1 / hybrid today (masked scores returned) |
| `masked=true`, `verify=true` | Masked (or hybrid) HNSW traversal as today → re-score those top-k candidates with **full-vector** distance → return top-`limit` by full score |
| `verify=true` without `masked=true` | Fail fast: `"verify requires focus.masked = true."` |

- Candidate set size is the same `limit` / `ef` path as masked search (no extra
  preselect invented).
- Scores under `verify=true` are **full-distance** scores (post-rescore), not
  the masked scores used during traversal.
- Works with hybrid `mask_from_layer` the same way: traversal unchanged, then
  full rescore of the returned candidates.
- `mask_from_layer=0` still routes to plain nearest (verify is a no-op there;
  scores are already full-distance).

## API field

REST / gRPC field name is exactly **`verify`** (bool, default false), inside
`focus` next to `masked` / `dims` / `mask_from_layer`:

```json
{
  "query": {
    "nearest": [0.1, 0.2, "..."],
    "focus": {
      "dims": [0, 1, 2, 3],
      "masked": true,
      "mask_from_layer": 1,
      "verify": true
    }
  },
  "limit": 10,
  "params": { "hnsw_ef": 64 }
}
```

## Design

Smallest diff: leave HNSW visited/heap logic untouched. Carry `verify` as the
fourth field of `QueryEnum::NearestMasked` / `QueryVector::NearestMasked`. After
search, `postprocess_search_result` (same hook as quantization rescore) rebuilds
a full-distance `FilteredScorer` and re-scores the candidate offsets.

```
REST `focus.verify`
  → gRPC proto `DimsFocus.verify`
  → collection `DimsFocus`
  → QueryEnum::NearestMasked(..., verify)
  → QueryVector::NearestMasked(..., verify)
  → HNSW / plain masked traversal (unchanged)
  → postprocess_search_result → full-distance rescore when verify=true
```

## Constraints (unchanged; verify does not relax them)

Dense only; no quantization / turbo storage; not with `with_dims_explained`;
local shards only.

## Live experiment (`run_xcut3_verify.py`)

Against a rebuilt XQdrant server (do **not** regenerate OpenAPI).

**Corrected evaluation (after the first X3 HTTP runs):**

- **Primary:** Recall@K vs **full-space** GT (masked vs verify).
- **Secondary:** subspace GT (often drops under verify — expected; not keep/skip).
- **Overfetch:** `--overfetch m` sends `limit=m·k` + `verify=true`, keeps top-k
  client-side (true fast-filter test; `m=1` is plain verify).
- **Hybrid:** `--layers -1 1` = fully masked + `mask_from_layer=1`.

```bash
cd /mnt/data/xq/DB_systems && source .venv/bin/activate
cd research/xcut3_verify_pass

# High-D
python run_xcut3_verify.py --mode http \
  --xqdrant-url http://127.0.0.1:6333 --qdrant-url http://127.0.0.1:6333 \
  --dataset synthetic --dimensions 768 1536 --num-vectors 50000 --queries 500 \
  --ratios 0.1 0.25 0.5 0.75 --overfetch 1 8 --layers -1 1 \
  --ef-search 128 --k 10 \
  --experiment-id xcut3_highD_fullGT_overfetch_hybrid_v1

# SIFT
python run_xcut3_verify.py --mode http \
  --xqdrant-url http://127.0.0.1:6333 --qdrant-url http://127.0.0.1:6333 \
  --dataset sift1m --queries 500 \
  --ratios 0.1 0.25 0.5 0.75 --overfetch 1 8 --layers -1 1 \
  --ef-search 128 --k 10 \
  --experiment-id xcut3_sift_fullGT_overfetch_hybrid_v1

# offline smoke
python run_xcut3_verify.py --mode simulated --dimensions 768 --queries 50
```

CSV columns include `masked_full_recall`, `verify_full_recall`,
`full_recall_recovered`, plus subspace counterparts and latency overhead.
Plots: `xcut3_verify_full_recall_d{D}_layer_{...}` (primary).

First-run pitfall: early harness scored only subspace GT, so verify looked harmful
by construction. Those runs are **superseded** — do not cite them for keep/skip.

## Measured results (authoritative)

| Run | Folder under `DB_systems/experiments/` |
|-----|----------------------------------------|
| High-D synthetic | `2026-07-14_09-34-50__xcut3_highD_fullGT_overfetch_hybrid_v1` |
| SIFT1M | `2026-07-14_09-46-22__xcut3_sift_fullGT_overfetch_hybrid_v1` |

Settings: `k=10`, `ef=128`, `--overfetch 1 8`, `--layers -1 1`, gather kernel.

| Finding | Detail |
|---------|--------|
| **`m=1` never moves Recall@K** | Full-space recall identical to masked in every cell (`+0.000`). Rescore only reorders the same `k` IDs. |
| **SIFT + `m=8` recovers full recall** when focus is large enough | e.g. ratio 0.5: ~0.26→**0.66**; ratio 0.75: ~0.46→**0.91** |
| **High-D synthetic stays broken** | Even `m=8`: full recall ≤ ~0.19 (tiny lifts +0.02–0.06). Matches X2 (subspace↔full overlap ~0.01–0.30). |
| **Hybrid `layer=1` ≈ all-masked** on full GT | Verifies X3 does not invent neighbors Option 2 failed to visit. |
| **Overfetch is not cheap** | `m=8` p50 ~46–52 ms (~+45 ms vs masked). On SIFT that is ~30× baseline. |

- `2026-07-13_17-07-08__xcut3_verify_pass__…` — subspace-GT-only SIFT

## Keep / skip (decision)

| Role | Decision |
|------|----------|
| API / scores | **Keep** `focus.verify` — returns full-distance scores after masked/hybrid traversal. |
| Paper subplot | **Keep** with overfetch: on coherent data (SIFT, large `D_sub/D`) masked search is a usable *filter*. |
| Latency / high-D fix | **Demote** — `m=1` does not recover Recall@K; `m=8` costs ~45 ms and fails on low-coherence high-D. |

If candidates never contain true full neighbors (low X2 overlap), need larger overfetch,
Option 3 (projected index), or a different approach — not verify alone.
